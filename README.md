# Career Base

大学生活・研究・就職活動・私生活の予定、ToDo、企業情報、メモをひとつにまとめる個人用Webアプリです。スマートフォンで素早く確認・登録でき、PCでもアプリらしく使えるレスポンシブUIを採用しています。

公開版: [https://career-base.vercel.app](https://career-base.vercel.app)

## 開発目的

情報がカレンダー、メモ帳、就活サイトなどに散らばる問題を解消し、日々の行動と就職活動を一か所で管理することが目的です。localStorageを端末キャッシュとして利用し、任意でSupabaseへ永続化・同期できるMVPとして保存層を分離しています。

## 現在実装されている機能

- 月曜日始まりの月間カレンダー、日付選択、予定の追加・削除
- 未完了／完了ToDo、期限順表示、期限切れ表示、完了切り替え
- 企業名・選考状況・直近の日付に絞った企業一覧、企業名検索、選考状況絞り込み
- 企業の追加、詳細モーダルからの編集・削除（PCは行一覧、スマホは2行表示）
- 左サイドバーの任意リスト作成・名前変更・削除、所属リストへの企業整理
- ○での複数選択、一括リスト移動・企業削除、企業名と所属リスト中心の簡素な入力フォーム
- 企業情報のデフォルト・締切順ソート、メモの更新日時による新しい順・古い順ソート
- タイトル・タグ中心のコンパクトなメモ一覧、キーワード検索、カテゴリ絞り込み
- PCの一覧＋直接編集、一覧の開閉／スマホの一覧・編集切り替え
- メモの書式編集（書体・サイズ・見出し・太字・斜体・下線・文字色・蛍光ペン・リスト・リンク）、Tabによる字下げ、元に戻す・やり直す
- メモの端末への即時自動保存、保存失敗表示と再試行、空のメモからの書き始め
- メモ一覧の○による複数選択、表示中の全選択・解除、一括カテゴリ移動・削除
- 登録済みデータの編集
- JSON形式でのバックアップ・復元・全データ削除
- `localStorage` によるデータ種別ごとの永続化
- Supabaseのメール／パスワード認証、利用者自身による新規登録、確認メール
- RLSによるユーザー単位のデータ保護と複数端末同期（Supabase接続時）
- 設定画面でのクラウド保存・読込・ログアウト
- モバイル優先の固定下部ナビゲーション、キーボード操作、フォーカス表示

## セットアップと起動

Node.js 20以上とnpmを用意し、リポジトリ直下で実行します。

```bash
npm install
npm run dev
```

Windows PowerShellの実行ポリシーにより `npm` が実行できない場合は、`npm.cmd install`、`npm.cmd run dev` のように `npm.cmd` を使用します。

ブラウザで `http://localhost:3000` を開くと `/calendar` に移動します。

### 企業リストとメモの使い方・データ互換性

企業リストは「すべて」「未分類」に加えて自由な名前で作成できます。PCは左のサイドバー、スマホは「表示リスト」で切り替えます。1社の所属リストは1つで、選考状況とは独立しています。「選択」を押すと行のつまみが○に変わり、一括リスト移動や企業削除ができます。全選択は表示中の企業だけが対象です。検索・リスト・選考状況の条件を変えると選択を解除します。

リストの「…」から名前変更・削除ができ、リスト削除時の所属企業は未分類へ戻ります。企業追加は企業名だけで可能です。所属リストには表示中のリストを初期設定し、選考・日程とその他の項目は折りたたんで表示します。折りたたんだまま保存しても既存の入力値は保持します。

企業とリストは既存の`career-base-companies`キーに`{ version: 1, companies, lists }`としてまとめて保存します。旧配列形式は読み込み時に対応し、最初の変更・復元で新形式になります。クラウドも既存の`companies` JSONB列に同じ形式を保存するため、追加のSQL設定は不要です。JSONバックアップでは従来の`companies`配列を保ち、任意の`companyLists`にリストを格納します。旧バックアップには空のリストを補います。リスト削除・一括移動・一括削除は1回の端末書き込みで反映し、失敗時は元の状態を維持します。

企業情報は「デフォルト」「締切順」で切り替えられます。デフォルトは保存されている配列順を維持します。締切未設定の企業は最後に表示します。メモは最終更新日時の「新しい順」「古い順」で並べ替えられます。どちらも表示順の切り替えで保存データ自体の配列順は変更せず、検索・絞り込みと組み合わせて使えます。

PCでは左の一覧を選ぶと右で直接編集でき、「一覧を閉じる」で本文を広く使えます。「一覧を表示」で戻せます。スマホでは一覧からメモを開き、「一覧に戻る」で切り替えます。編集中も右上の「＋ 追加」から、既存メモの保存内容を残して新しいメモへ切り替えられます。

メモ一覧の「選択」でつまみが○に変わり、企業と同様に複数選択できます。表示中のメモだけを全選択でき、検索やカテゴリ変更時には選択を解除します。「カテゴリ移動」で既存カテゴリへまとめて移動でき、「メモ削除」では対象のタイトルと件数を確認してから削除します。一括操作は1回の端末書き込みで保存し、失敗時は元のデータと選択を維持します。開いているメモを移動した場合は編集画面のカテゴリも更新し、削除した場合は編集画面を閉じます。

本文の選択範囲に書式バーから装飾を適用できます。本文内のTabはタブ文字を挿入し、Shift＋Tabは直前の字下げを解除します。リスト内では階層を変更します。スマホでは字下げボタンを使えます。Escで本文から書式バーへ移動できます。

メモは入力ごとに端末へ保存し、従来どおりログイン時はクラウドへの自動保存を予約します。「この端末に自動保存済み」はクラウド同期の完了を示すものではありません。端末への保存に失敗した場合は書きかけを表示したままエラーと再試行を表示し、保存できるまで別メモへの切り替えを止めます。空のタイトルは「無題のメモ」として保存します。

従来の`content`は検索用の通常テキストとして維持し、書式は任意の`richContent`に保存します。既存のメモや旧バックアップは変換操作なしで開けます。カテゴリ・タグ・企業ID・作成日時を維持し、書式も既存のJSONバックアップとSupabaseのJSONB同期に含まれるため、DBの変更は不要です。

### Supabase同期を使う場合

1. Supabaseでプロジェクトを作成する
2. SQL Editorで `supabase/migrations/20260713_create_career_base_data.sql` を実行する
3. AuthenticationのSign In / ProvidersでEmailの新規登録を有効にし、Confirm Emailを有効にする
4. AuthenticationのURL ConfigurationでSite URLを公開URL、Redirect URLsに公開版と`http://localhost:3000/**`を登録する
5. 一般の利用者へ確認メールを送る場合は、AuthenticationのSMTP設定でCustom SMTPを有効にする
6. AuthenticationのEmail Templatesで`Confirm signup`の件名と本文を設定する
7. `.env.example` を参考に、プロジェクト直下へ `.env.local` を作成する

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

ブラウザ用のPublishable keyだけを使用し、Secret keyや`service_role`キーは設定しないでください。`.env.local`はGit管理の対象外です。

Custom SMTPにはSMTPサービスで発行したホスト、ポート、ログイン名、SMTPキーを設定します。SMTPキーはSupabase Dashboardへ直接登録し、ソースコード、`.env.local`、GitHub、READMEには保存しないでください。確認メール本文にはSupabaseが発行するURLを埋め込むため、`{{ .ConfirmationURL }}`を残します。

接続情報がない場合も、従来どおりlocalStorageだけで利用できます。設定画面からログインした際、クラウドにデータがなければ現在の端末データを保存し、既存データがあればクラウドの内容を端末へ反映します。その後の追加・編集・削除は自動でクラウドへ保存されます。

「クラウドから読込」は端末内データをクラウドの内容で置き換えます。ログアウト時は別ユーザーへの混入を防ぐため端末キャッシュを消去し、次回ログイン時にクラウドから復元します。複数端末で同時に編集した場合は最後に保存された内容が優先されるため、重要な変更の前にはJSONバックアップを作成してください。

静的検査とビルド:

```bash
npm run lint
npm run typecheck
npm run build
```

ブラウザテスト（本番ビルドとポート3100の検証サーバーを自動起動）:

```bash
npx playwright install chromium
npm run test:e2e
```

インストール済みのChromeを使う場合は、PowerShellで`$env:PLAYWRIGHT_CHANNEL='chrome'`を設定してから`npm run test:e2e`を実行できます。テストは独立したブラウザの保存領域を使い、普段利用しているメモには触れません。

## Vercelへの公開

個人・非商用での利用を想定し、VercelのHobbyプランへ公開できます。

1. GitHubで空のリポジトリを作成する
2. このプロジェクトをGitHubへpushする
3. VercelへGitHubアカウントでログインする
4. Vercel Dashboardで「Add New」→「Project」を選択する
5. GitHubへpushしたリポジトリをImportする
6. Framework Presetが「Next.js」であることを確認してDeployする

VercelでもSupabase同期を使う場合は、Project SettingsのEnvironment Variablesへ `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` を追加し、Production・Preview・Developmentの必要な環境を選択して再デプロイします。接続情報を設定しない場合、データは従来どおり各ブラウザのlocalStorageに保存されます。

## 現在の制約と注意事項

- パスワード再設定、CAPTCHA、アカウント削除は未実装です
- 公開URLでは誰でも新規登録できるため、広く案内する前にCAPTCHAの導入を推奨します
- 無料メールアドレスをSMTPの送信元にすると、確認メールが迷惑メールへ振り分けられる場合があります
- 同じデータを複数端末から同時編集した場合、最後にクラウドへ保存された内容が優先されます
- ブラウザの保存データを消去するとlocalStorageのデータも消えるため、未ログインで利用する場合はJSONバックアップを作成してください

### カレンダーの祝日データ

内閣府「国民の祝日」CSV（https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv）を加工し、`src/data/japanese-holidays.json` に保存しています。現在の収録範囲は1955〜2027年です。振替休日なども公式CSVの名称で表示します。画面表示時の外部通信は不要です。

内閣府が翌年分を公表した後は `npm run update:holidays` で更新し、生成されたJSONもコミットしてください。未収録の年はカレンダーに「祝日データは未取得」と表示します。出典：https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html
